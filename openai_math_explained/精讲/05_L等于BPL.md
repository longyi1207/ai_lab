## 0. 先说结论：这一章要讲明白的一件事

设想一台内存极小的机器：输入可以随便读，但工作内存只够存**几个指针**。这台机器如果能掷硬币，能不能解决更多问题？

这一章要讲清楚下面这条因果链：

> 小内存机器的整个计算 ⟺ 一张"配置图"上的随机游走 ⟺ 接受概率 = 一个大矩阵的幂次之和 ⟹ 去随机化 = 用很少的内存把这个概率算准 ⟹ 难点在于"算准"需要的精度和递归层数会把内存吃掉。

**L** 是确定性小内存计算能解决的问题，**BPL** 是"小内存 + 掷硬币 + 允许小概率出错"能解决的问题。几乎所有人都相信 L = BPL，但 1999 年以来最好的无条件结果只到"BPL 能用 (log n)^1.5 的内存确定性模拟"，离 log n 一直差一个 √log n 的因子。

OpenAI 声称把这个差距完全消掉了：**L = RL = BPL**。这个结论本身从来没有多少人怀疑，难的是证明。它有 Lean 形式化，但截至 2026-10-08，没有人类专家公开说自己读完并核实了这篇 108 页的论文。

读完这一章，你应该能用自己的话讲出：
- 为什么"O(log n) 比特内存"大约等于"能存常数个指针"，以及为什么这样的机器一定在多项式时间内停机；
- 随机游走为什么能用极小的内存解决无向图连通性，又为什么同样的办法在有向图上会失效；
- "种子长度"为什么是这个领域的核心指标，Nisan 的 log² n 和目标 log n 之间差在哪里；
- OpenAI 的结论如果为真，意味着什么、**不**意味着什么（不意味着 P = BPP，也不意味着 L = NL）。

## 1. 空间复杂度：内存是一种资源

### 1.1 时间和空间

衡量算法有两把尺子：
- **时间**：走了多少步。
- **空间**：同一时刻最多占用多少比特的**工作内存**。

这里有个关键约定：**输入不算在空间里**。输入放在一条"只读带"上，机器可以来回读，但不能写。只有"工作带"（可读可写的草稿纸）计入空间。这样才能讨论"比输入还小的内存"。

工程上的类比是**流式处理加随机访问**：数据放在一块只读的大盘上，你可以 seek 到任何位置去读，但本地 RAM 只有几十个字节。

### 1.2 对数空间 L：能存常数个指针

**L**（logspace）= 确定性机器、工作内存 O(log n) 比特就能判定的问题。

为什么是 log n？因为一个能指向输入中任意位置的指针，需要 ⌈log₂ n⌉ 比特。O(log n) 比特就是"常数个指针或计数器"。

| 输入长度 n | log₂ n（一个指针） | (log₂ n)^1.5 | (log₂ n)² |
|---|---|---|---|
| 10³ | 10 | 31 | 99 |
| 10⁶ | 20 | 89 | 397 |
| 10⁹ | 30 | 163 | 894 |
| 10¹² | 40 | 252 | 1,589 |

（脚本实算，单位是比特。）输入有 10⁹ 字节时，L 允许的内存只有几十到几百比特，相当于几个寄存器。(log n)² 和 (log n)^1.5 这两列后面会反复出现，它们是去随机化历史上的两个里程碑。

【检查 1】输入是 10⁹ 个顶点的图。存一个顶点编号需要几个比特？存"当前顶点 + 目标顶点 + 一个步数计数器（最多数到 n³）"一共大约几个比特？

### 1.3 一个重要事实：对数空间的确定性机器一定在多项式时间内停机

机器在某一时刻的全部状态叫**配置**（configuration）：控制状态 + 各个读写头的位置 + 工作带的内容。工作带只有 c·log n 比特，所以内容最多有 2^(c·log n) = n^c 种；读头位置有 n 种；控制状态是常数种。所以**配置总数是 n 的多项式**。

一台确定性机器如果停机，就不可能把同一个配置经历两次（否则会死循环）。所以它的步数不超过配置数，也就是多项式时间。

**这个"配置数是多项式"的事实是整章的基石。** 后面所有内容都可以看成在一张多项式大小的"配置图"上做事。

## 2. 随机性能买到什么

### 2.1 例子：多项式恒等式检验

给你两个用公式写出的多项式，问它们是否恒等。比如 (x+y)² 和 x² + 2xy + y²。

这个例子手动展开就能判断。难的情况是：多项式写成一个很紧凑的公式或电路，展开后会有指数多项（比如一个 n×n 行列式，展开后有 n! 项）。这时候**确定性**的快速算法至今未知，这就是 **PIT 问题**（polynomial identity testing）。[已确立]

随机算法很简单：**随机代入几个数，看两边是否相等。**
- 如果恒等，代什么都相等。
- 如果不恒等，两边的差是一个非零多项式，它的根很少。Schwartz–Zippel 引理说：从大小为 |S| 的集合里随机取值，一个 d 次非零多项式取到 0 的概率 ≤ d/|S|。[已确立]

**手算例子**：错误的"恒等式" (x+y)² = x² + y²。两边的差是 2xy，是 2 次多项式。x 和 y 都从 {0, …, 99} 中随机取，共 10,000 种组合。

【检查 2】有多少种组合会让两边恰好相等（也就是"骗过"随机检验）？

脚本实算：199 种，占 1.99%。Schwartz–Zippel 的上界是 d/|S| = 2/100 = 2%，吻合。随机代一次，被骗的概率不到 2%；独立代 10 次，被骗的概率不到 2%¹⁰ ≈ 10⁻¹⁷。

### 2.2 P 和 BPP

- **P**：确定性多项式时间能解决的问题。
- **BPP**：多项式时间 + 随机比特，每个输入上出错概率 ≤ 1/3 的问题。

1/3 这个数不重要，因为可以**放大**：独立跑 k 次，取多数票。

| 重复次数 k | 多数票出错概率（单次正确率 2/3） | 计数器需要的比特 |
|---|---|---|
| 1 | 3.3 × 10⁻¹ | 1 |
| 11 | 1.2 × 10⁻¹ | 4 |
| 51 | 6.9 × 10⁻³ | 6 |
| 101 | 2.7 × 10⁻⁴ | 7 |
| 201 | 5.5 × 10⁻⁷ | 8 |

（脚本实算，二项分布尾部求和。）注意最后一列：放大只需要一个计数器，**对小内存机器同样可用**。这是 BPL 的定义里阈值取 2/3 还是 0.51 都无所谓的原因。

**主流猜想是 P = BPP**，也就是随机性不带来本质提升。证据很强：Impagliazzo–Wigderson 1997 证明了，只要某些问题需要指数大小的电路（一个大家普遍相信的"难度假设"），就有 P = BPP。[已确立] 但**无条件**证明 P = BPP 被认为极难：Kabanets–Impagliazzo 2004 证明了，哪怕只是把 PIT 去随机化，也会推出一些我们目前完全证不出来的电路下界。[已确立]

这就是"难度换随机性"（hardness vs. randomness）的框架：**去随机化和证明下界几乎是同一件事。** 时间版本被这道墙挡住了。空间版本没有已知的同类障碍，所以 L = BPL 一直被看作"最有希望无条件证出来的去随机化猜想"。

## 3. RL 和 BPL：小内存 + 掷硬币

### 3.1 定义

机器多了一个能力：每一步可以拿到一枚新的公平硬币。限制是：
- 工作内存 O(log n) 比特；
- 对**所有**硬币序列，都在多项式时间内停机；
- **硬币是一次性的**：读完就没了，想再用必须自己存到工作带上，而工作带只有 log n 比特。

最后一条很关键。时间版的 BPP 可以把随机串存下来反复读，小内存机器不行。它只能"边掷边用"，像一个在线的、单遍的流。

两种出错方式：
- **RL**（单边错）：答案是"否"时一定拒绝；答案是"是"时至少以 1/2 概率接受。
- **BPL**（双边错）：答案是"是"时至少以 2/3 概率接受；答案是"否"时至多以 1/3 概率接受。

已知的包含关系 [已确立]：

```
L ⊆ RL ⊆ BPL ⊆ L^{3/2}（Saks–Zhou 1999）
RL ⊆ NL ⊆ L²（Savitch 1970）
```

NL 是"非确定性"对数空间（机器可以"猜"）。有向图的可达性是 NL 的代表问题。

### 3.2 整个计算 = 一张图上的随机游走

用第 1.3 节的事实：随机机器在输入 x 上的所有配置是多项式多个。把每个配置画成一个点；如果从配置 u 掷一枚硬币能走到配置 v，就从 u 向 v 连一条边，权重 1/2。

于是**机器在 x 上的运行 = 在这张配置图上从起点出发的随机游走**；**接受概率 = 游走在时限内到达"接受"配置的概率**。

**手算例子**：一个只有 3 个状态的玩具机器，每步掷一枚硬币：
- 状态 0：正面去 0，反面去 1
- 状态 1：正面去 2，反面去 0
- 状态 2：吸收（一直留在 2），代表"接受"

写成转移矩阵 T，从 v = (1, 0, 0) 开始，每走一步就算 v ← vT：

| 步数 | P(在 0) | P(在 1) | P(在 2) |
|---|---|---|---|
| 1 | 0.5 | 0.5 | 0 |
| 2 | 0.5 | 0.25 | 0.25 |
| 3 | 0.375 | 0.25 | 0.375 |
| 4 | 0.3125 | 0.1875 | 0.5 |

（脚本实算；另外把 2⁴ = 16 种硬币序列全部穷举了一遍，恰好 8 种走到状态 2，和矩阵算出的 0.5 一致。）

【检查 3】只用手算，验证第 2 步的分布 (0.5, 0.25, 0.25)。

这就把问题变成了线性代数：**接受概率 = 转移矩阵的若干次幂作用在起始向量上。** OpenAI 论文开头也是这样做的：它把机器转成一个矩阵 S，接受概率是 (I − S)⁻¹e 的一个分量，等价于 Σⱼ Sʲe（第 7.2 节）。

### 3.3 为什么"直接算"不在 L 里

既然只是矩阵幂，确定性地算出来不就行了？问题是**内存**：
- 矩阵是 n^c × n^c 的，存不下，只能需要哪一项就现算哪一项。
- 用"反复平方"求 Tᵗ 时，Tᵗ 的每一项依赖 T^(t/2) 的项，T^(t/2) 的每一项又依赖 T^(t/4) 的项……递归有 log t ≈ O(log n) 层，每一层都要记住自己算到哪了（O(log n) 比特），再加上数值精度的位数。
- 总空间 ≈ 层数 × 每层 = O(log n) × O(log n) = **O(log² n)**。

这就是 Borodin–Cook–Pippenger 1983 证明的"随机对数空间 ⊆ 确定性 log² 空间"背后的直觉，和 Savitch 定理的"递归栈"是同一个结构。[已确立] **整个领域 40 年的工作，就是想把这个"层数 × 每层"压下去。**

## 4. 无向图连通性：随机游走的经典胜利

### 4.1 问题

**USTCON**（undirected s-t connectivity）：给一张无向图和两个点 s、t，问它们是否连通。

用 BFS/DFS 很容易，但需要一个"已访问"数组，占 n 比特。只有 O(log n) 比特时怎么办？

### 4.2 随机游走算法（AKLLR 1979）

Aleliunas、Karp、Lipton、Lovász、Rackoff 在 1979 年给出了一个极简的算法 [已确立]：

```
v ← s
重复 N 步：
    如果 v = t，回答"连通"
    v ← v 的一个随机邻居
回答"不连通"
```

只需要记"当前顶点 v"和"步数计数器"，O(log n) 比特。如果 s、t 不连通，它永远不会走到 t，所以**不会把"否"说成"是"**；如果连通，只要 N 足够大，就能高概率走到。这正好是 RL 的单边错形式。

他们证明的关键界：在连通图上，随机游走访问遍所有顶点的期望步数（**覆盖时间**，cover time）≤ 2|E|(n−1)，其中 |E| 是边数。由于 |E| ≤ n²，所以 ≤ n³ 量级。取 N = 4n³，用马尔可夫不等式就能把失败概率压到 1/2 以下。

### 4.3 脚本实测

**小例子**：6 个顶点，边是 0–1、0–2、1–2、2–3、3–4、4–5（一个三角形接一条尾巴）。从 0 走到 5。

一次实际模拟的轨迹（脚本，随机种子 1）：

```
0 1 0 2 0 2 1 2 3 4 3 2 1 0 2 1 0 2 1 0 1 2 0 1 0 1 2 3 2 1 0 1 2 1 0 2 0 1 2 1 0 2 3 2 0 2 0 2 3 4 3 4 5
```

走了 52 步。它在三角形里绕了很久，因为从 2 出发只有 1/3 的概率往尾巴走，走到 3 后又有 1/2 的概率退回来。

20,000 次模拟的平均：从 0 到 5 约 29.1 步，覆盖全图约 30.4 步。上界 2|E|(n−1) = 2·6·5 = 60，实测在界内。

**几类图的命中时间**：

| 图 | n | 实测 / 精确的期望步数 | 对照 |
|---|---|---|---|
| 路径（从一端到另一端） | 10 | 81.7（模拟） | 精确值 (n−1)² = 81 |
| 路径 | 40 | 1,523.7（模拟） | (n−1)² = 1,521 |
| "棒棒糖"（n/2 个点的完全图 + n/2 个点的尾巴） | 40 | 8,019（解线性方程组，精确） | n³ = 64,000，比值 0.125 |
| 棒棒糖 | 80 | 64,039（精确） | n³ = 512,000，比值 0.125 |

（脚本实算。）棒棒糖图是随机游走最糟的情形：游走在完全图里打转，很少进入尾巴，进入后又容易退回来。Brightwell–Winkler 1990 证明了 n 个点的图上最大命中时间约为 (4/27)n³ ≈ 0.148n³（团占 2/3 时取到）。[已确立，⚠ 常数凭文献记忆，未打开原文核对] 我们的"各占一半"版本是 0.125n³，同一量级。所以 **n³ 步一般够用，也基本不能更少**。

### 4.4 为什么同样的办法在有向图上失败

考虑一张有向图：顶点 0, 1, …, n，从 i 出发有两条边，一条到 i+1，一条回到 0。目标是 n。

从 0 出发的随机游走要连续 n 次都选"前进"才能到达，期望步数是 2^(n+1) − 2：

| n | 期望步数（精确解线性方程组） |
|---|---|
| 5 | 62 |
| 10 | 2,046 |
| 20 | 2,097,150 |
| 30 | 2,147,483,646 |

（脚本实算，与公式完全吻合。）**指数级**。所以随机游走解决不了有向图可达性。有向可达性是 NL 完全的，它是否在 L 里（L = NL?）至今开放，**与本章的结果无关**。

【检查 4】对 n = 2 手算这个期望值。提示：记 hᵢ 为从 i 出发到达 n 的期望步数，hₙ = 0，hᵢ = 1 + ½hᵢ₊₁ + ½h₀。

**无向图为什么好**：无向边可以原路返回，随机游走不会被"单向陷阱"困住。线性代数上，无向图的转移矩阵是对称的（经过归一化后），它的特征值都是实数，"混合"速度由谱间隙控制，这是第 5 节的主角。

## 5. Reingold 2005：无向连通性在 L 里（SL = L）

### 5.1 历史

AKLLR 之后，大家想去掉 USTCON 的随机性：
- Nisan–Szemerédi–Wigderson 1992：O(log^1.5 n) 空间 [已确立]
- Armoni–Ta-Shma–Wigderson–Zhou 2000：O(log^(4/3) n) 空间 [已确立]
- **Reingold 2005**：O(log n) 空间，即 USTCON ∈ L。[已确立] STOC 2005，JACM 2008，获 Gödel 奖。

SL（symmetric logspace）是以 USTCON 为完全问题的类，所以这个结果也写成 **SL = L**。这是"拿掉一个具体问题的随机性"的里程碑，但只针对无向图这一种结构。

### 5.2 扩张图：连通得"非常好"的图

**扩张图**（expander）是度数很小（每个点只连常数条边）却连通得极好的图：任何一小块顶点集合，都有很多边连到外面。

衡量方式是**谱间隙**：随机游走转移矩阵的最大特征值是 1，第二大特征值 λ₂，间隙 = 1 − λ₂。间隙越大，随机游走越快"忘掉"起点。大致上，混合需要的步数 ∝ (log n) / 间隙。

| n | 环（每点度 2）的间隙 | 1/间隙 | 随机 4-正则图的间隙 | 1/间隙 |
|---|---|---|---|---|
| 64 | 0.00482 | 208 | 0.162 | 6.2 |
| 256 | 0.00030 | 3,320 | 0.138 | 7.2 |
| 1024 | 0.00002 | 53,122 | 0.134 | 7.4 |

（脚本实算，numpy 求特征值；随机 4-正则图用两个随机置换的并构造。）环的间隙按 1/n² 掉到 0，随机 4-正则图的间隙稳定在常数（理论最优值 1 − 2√3/4 ≈ 0.134，即 Ramanujan 界，实测已经贴着它了）。

**扩张图的直径只有 O(log n)。** 所以如果图是常数度的扩张图，可以**穷举所有长度为 O(log n) 的路径**：每一步只有常数种选择，一条路径用 O(log n) 比特就能描述，总共 d^O(log n) = 多项式条。一个计数器挨个试即可，不需要随机性。

### 5.3 Reingold 的想法：把任意图"改造"成扩张图

难点是输入的图不一定是扩张图。Reingold 用两种操作反复改造它（每个连通分量分别改造）：
1. **平方**（powering）：新图里，两点相邻当且仅当原图里它们之间有长度为 2 的路径。谱间隙大约翻倍（λ₂ 变成 λ₂²），代价是度数平方。
2. **zig-zag 积**（Reingold–Vadhan–Wigderson 2000）：用一个小的固定扩张图"替换"每个顶点，把度数降回常数，间隙只损失一个常数因子。[已确立]

交替做 O(log n) 轮，间隙从 1/poly(n) 增长到常数。

**为什么不吃内存**：改造后的图**从不显式存储**。要查"新图里顶点 v 的第 i 个邻居"，就递归地向上一层图发查询。关键是 zig-zag 的设计让每一层只多花**常数**比特（而不是 log n 比特）。O(log n) 层 × O(1) 比特 = O(log n)。

对照第 3.3 节："层数 × 每层"里，Reingold 把"每层"从 log n 压到了常数。工程类比：多层虚拟地址翻译，每一层只需记几个比特的偏移，而不是一个完整地址。

**局限**：zig-zag 和平方都依赖图的对称性（无向）。一般 BPL 计算的配置图是有向的，Reingold–Trevisan–Vadhan 2006 把它推广到了"正则有向图"等特殊情形，但没有覆盖一般情形。[已确立]

## 6. 一般 BPL 的去随机化：25 年卡在 3/2

### 6.1 伪随机生成器和"种子长度"

一个最朴素的去随机化办法：**把所有随机串都试一遍，数一数接受的比例。** BPL 机器读 poly(n) 个随机比特，有 2^poly(n) 种随机串，太多了。

**伪随机生成器**（PRG）的想法：用一个短的**种子**（seed）生成一长串"看起来随机"的比特。"看起来随机"是相对于某一类观察者说的：对任何一台小内存机器，用伪随机串和用真随机串得到的接受概率几乎相同。

有了种子长度为 s 的 PRG，去随机化就是：枚举全部 2^s 个种子，每个跑一遍，统计。需要的空间约为 s + O(log n)。

| 种子长度 | 需要枚举的种子数 | 去随机化的结果 |
|---|---|---|
| poly(n)（真随机） | 2^poly(n) | 无用 |
| O(log² n)（Nisan 1992） | n^O(log n)（拟多项式） | BPL ⊆ L² |
| O(log n)（梦想） | poly(n) | L = BPL |

所以**整个问题可以归结为：对小内存机器，能不能造出种子长度 O(log n) 的 PRG？** 这个问题 30 多年没有解决。

### 6.2 Nisan 的生成器（1992）：为什么是 log²

Nisan 的核心观察是：**小内存机器记不住自己用过哪些随机比特，所以可以安全地"复用"。** [已确立]

构造方式（简化）：
- 种子 = 一个 O(log n) 比特的随机串 x，加上 k 个随机哈希函数 h₁, …, h_k，每个 O(log n) 比特。
- 第 1 层：输出 x, h₁(x)。
- 第 2 层：输出 x, h₁(x), h₂(x), h₂(h₁(x))。
- 每加一层，输出长度翻倍。

直觉：机器读完前半段后，它的状态只有 O(log n) 比特，几乎"忘了"前半段的具体内容；所以后半段用"前半段过一次哈希"代替，机器察觉不到。

要输出 poly(n) 个比特，需要 k = O(log n) 层，每层一个 O(log n) 比特的哈希函数，种子总长 O(log n) × O(log n) = **O(log² n)**。又是"层数 × 每层"。

Nisan 1994 又证明了这个模拟可以同时做到多项式时间和 O(log² n) 空间（BPL ⊆ SC）。[已确立]（注：Borodin–Cook–Pippenger 1983 已经用矩阵方法得到了 log² 空间，但没有多项式时间。）

### 6.3 Saks–Zhou 1999：3/2

Saks 和 Zhou 把 Nisan 的 log n 层切成 √log n 段，每段 √log n 层。每段用 Nisan 的方法近似算出一个矩阵幂，然后把结果的低位**随机地舍入**掉。这样每段的结果几乎不依赖具体用了哪组哈希函数，于是**所有段可以共用同一组哈希函数**。[已确立；这里的描述是大幅简化，⚠ 细节请看原文]

空间：一组哈希函数 √log n × log n，加上递归 √log n 段 × 每段 log n，合计 **O(log^1.5 n)**。

### 6.4 之后的进展和停滞

| 年份 | 结果 | 确定性空间 |
|---|---|---|
| 1983 | Borodin–Cook–Pippenger | log² n |
| 1992 | Nisan PRG | log² n |
| 1999 | Saks–Zhou | log^1.5 n |
| 2021 | Hoza（加权伪随机性） | log^1.5 n / √(log log n) |
| 2026 | **OpenAI（声称）** | **log n** |

（Hoza 的界据 OpenAI 论文 §1.1 引用的 [19, Theorem 1.6 and Corollary A.5] 和我的记忆；本 deck 作者的研究笔记里原先标了 ⚠，这次核对了论文的引用，两者一致。）

Hoza 2021 只省下了 √(log log n)，对 n = 10⁹ 也就是省掉约 2.2 倍。一般 BPL 的指数在 3/2 附近卡了 27 年。

**中间还发现了很多"特殊结构"上的胜利**：Reingold（无向图）、Reingold–Trevisan–Vadhan（正则有向图）、Ahmadinejad 等（Eulerian 图上高精度地算随机游走概率）、Cohen–Doron–Sberlo–Ta-Shma（长随机矩阵乘积）。[已确立] 另外，Cheng–Hoza 2022 证明了：只要有一个对数空间可枚举的"命中集"（只保证找到一个接受的输入，比 PRG 弱），就能推出 L = BPL。[已确立] 这些都说明，问题的"形状"已经被摸得很清楚，就差最后一步。

## 7. OpenAI 声称了什么

### 7.1 主结果

论文 *Exact Derandomization of Logarithmic Space: L = RL = BPL*（2026-09-23，108 页，作者署名 "OpenAI"）。摘要只有一句：

> "We prove L = RL = BPL, resolving the derandomization problem for polynomial-time randomized logarithmic space."

翻译：每一个"多项式时间 + 对数空间 + 有界出错概率"的随机计算，都能用确定性对数空间模拟。

论文还给出一个**更强的定量版本**（定理 1.2）：对任何这样的随机机器 M 和输入 x，可以确定性地把接受概率估计到 2^(−q) 的精度，用 O(log n + q) 的空间和 poly(n)·2^O(q) 的时间。q = O(log n) 时，就是任意多项式倒数的精度都能在对数空间里算出来。这比"判断概率是大于 2/3 还是小于 1/3"强得多，它连"没有间隙"的概率都能估计。

此外第 13 节给出一个**编译器**：输入一台随机机器的源程序和它的时间/空间界，输出一个确定性判定器和显式的资源界。

### 7.2 方法的直觉（我只读了引言 §1–§2，以下是简化版）

1. **变成矩阵求逆**（§2）。把机器在输入 x 上的配置图写成矩阵 S（每个配置带一个时间戳，边只指向更晚的时间，所以 S 是"严格向前"的、幂零的）。接受概率是 p₀ = (I − S)⁻¹e 在起点处的值，e 标记接受配置。这和第 3.2 节的玩具例子是同一件事。
2. **"修正与副本层级"**（§4）。作者用一串变换把 S 替换成新的矩阵 C₁, C₂, …，每一步把一部分转移概率"转移"到奖励向量里（利用恒等式 I − D = (I + E)(I − C)），同时复制一些顶点来分散大的矩阵项。经过 O(log n) 个阶段后，只要沿着一条"主副本"路径读出累计奖励，就能以多项式倒数的误差得到接受概率。
3. **只用 O(log n) 个随机比特估计**（§5–§9）。这些矩阵不显式存储，而是用一个**共享的有限随机环境** σ（长度 O(log n) 的编码）做抽样估计。论文证明：在超过 3/4 的 σ 上，估计值是准的；而且对**每一个** σ（包括估计不准的那些），估计过程都会在 O(log n) 空间内停机。
4. **枚举 + 取中位数**（§12）。σ 只有 O(log n) 比特，所以全部 σ 只有多项式个。挨个枚举，取中位数，和 1/2 比较。这一步就是第 6.1 节"枚举种子"的思路，只不过它不是造一个通用 PRG，而是针对这一个估计器把随机性压到了 O(log n) 比特。
5. **让递归不吃内存**（§9–§11）。用短的**指纹**（多项式求值 + 仿射哈希）代替完整的顶点地址做比较；用一个共享的"催化"比特向量；用 Cook–McKenzie 的"沿轮廓遍历树"技巧找回入边，而不用栈。每个递归调用保留的数据被控制在 A(w − w′) + D(t − j) 比特以内，沿调用链**伸缩求和**（telescoping），总和是 O(log n)。

把第 5 步和第 3.3 节、第 5.3 节对照：它仍然是"层数 × 每层"的问题，解法是让每层花费的比特数和"递归预算的下降量"挂钩，整条调用链加起来不超过一个 O(log n) 的总预算。工程类比：一个递归调用栈，但每一帧的大小受一个全局配额约束，配额沿栈向下递减。

**两个让我意外的细节**：
- §6 的"条件平均"的混合界，依赖 Shalom 1999 关于 **Kazhdan 性质 (T)** 的结果（一个群论里的深刻性质）。[OpenAI 声称] 群论工具出现在小内存去随机化里，这在已有文献里不常见。[推测]
- "共享催化比特向量"让人想到近年的**催化计算**（catalytic computing）：借一块已经写满数据的内存来用，用完原样还回去。Cook–Mertz 用它把树求值问题的空间降到 O(log n · log log n)，Ryan Williams 2025 在此基础上证明了"时间 t 的计算可以用约 √(t log t) 空间模拟"。[已确立] 如果 OpenAI 的证明成立，催化技巧可能又一次是关键零件。[推测，⚠ 没读到 §11 的细节]

## 8. 它被核实到什么程度

### 8.1 Lean 陈述：你可以自己读懂

`lean/ComparatorChallenges/LogspaceEquality.lean` 的最后一行是：

```lean
theorem exact_logarithmic_space_derandomization :
    L = RL ∧ RL = BPL
```

逐词翻译：
- `L = RL ∧ RL = BPL`：L 等于 RL，**并且** RL 等于 BPL。

这一行太短了，真正的内容全在**定义**里。和准黎曼猜想不同，这里的 L、RL、BPL **不是** Mathlib 的标准定义（Mathlib 里没有这些复杂度类），而是 OpenAI 在挑战文件里自己写的。所以要审的是定义。下面是我逐条读的结果：

| 定义 | 它说了什么 | 是否符合教科书 |
|---|---|---|
| `Machine q w h` | 有限状态机，h 个只读输入头，w 条二进制工作带；每步读一个硬币 b | 是，标准多带图灵机 |
| `readInput` | 输入两端有端标记 | 是 |
| `step` | 已输出（停机）的配置不再变化 | 是 |
| `spaceThrough` | 到时刻 t 为止，每条工作带**访问过的不同格子数**之和 | 是，而且比较严格（访问过的空白格也算） |
| `LogSpace` | 存在 c > 0，对**所有**输入、**所有**硬币序列、**所有**时刻，空间 ≤ c·⌈log₂(n+2)⌉ | 是 |
| `Deterministic` | 转移函数不依赖硬币 | 是 |
| `acceptanceProbability` | 在时钟 t 时，2^t 种硬币串里停在"接受"的比例 | 是 |
| `L` | 确定性 + 对数空间 + 对每个输入都在某个时刻给出正确答案 | 是（没写时间界，但第 1.3 节说明确定性对数空间停机机器自动是多项式时间） |
| `RL` | 对数空间 + 对**所有**硬币序列在 c·(n+2)^k 步内停机 + 是则概率 ≥ 1/2，否则概率 = 0 | 是 |
| `BPL` | 同上，阈值 2/3 和 1/3 | 是 |

**我的判断：符合标准定义。** 一个值得注意的选择是"所有硬币序列都在多项式时间内停机"，这是标准的 BPL；如果去掉时间限制，得到的是另一个类（论文 §1.1 也专门强调了"空间界"和"同时的时空界"的区别）。这与作者研究笔记的结论一致。

## 9. 如果为真，意味着什么（以及不意味着什么）

### 9.1 对复杂性理论

1. **第一个无条件"完全去掉随机性"的自然计算资源类。** 在"对数空间 + 多项式时间"这个范围里，掷硬币一点用都没有。这回答了 AKLLR 1979 年就明确提出的问题。
2. **它不蕴含 P = BPP。** 时间版本被"去随机化 ⇒ 电路下界"那道墙挡着（第 2.2 节），空间版本的证明绕过了它，但没有拆掉它。PIT 的确定性多项式时间算法依然未知。
3. **它不蕴含 L = NL，更离 P vs NP 很远。** 有向图可达性（第 4.4 节）依然不知道能否在对数空间里解决。新的包含关系图是：

```
L = RL = BPL ⊆ NL ⊆ L²
```

4. **定理 1.2 可能比 1.1 更有用。** 能在对数空间里高精度估计随机游走概率，意味着很多小空间线性代数问题（比如对 Laplacian 求解、马尔可夫链的平稳分布）可能有新的确定性算法。[推测]
5. **技术可能比结论更重要。** Aaronson 说结论"从来没人认真怀疑过"，所以领域真正想要的是**证明方法**。可惜目前没人读懂它。如果证明成立却没人能提炼出可复用的思想，这会是一个很奇怪的局面：问题关闭了，但领域没学到东西。[推测]

### 9.2 对工程

对实际系统几乎没有直接影响：实践中的随机算法（哈希、采样、Bloom filter）本来就够快，也多不在"对数空间"这个极端设定里。定理只保证确定性替代算法**存在**，多项式的次数和常数很可能是天文数字。[推测] 对流式算法的含义也有限：流式模型只能单遍读输入，L 允许反复读。

### 9.3 对 AI

- 和其他头条结果一样，这是"AI 在公认的硬核开放问题上给出证明，并附带机器检查"的案例。
- 它的特点是**结论大家都信，难在证明**。这类问题对 AI 也许特别合适：方向明确，不需要"猜对结论"，需要的是把一个 108 页的复杂构造在每一步都做对，而 Lean 正好能逐步检查。[推测]
- 对 AI 安全研究的启示，和本 deck §16 一样：有了 Lean 之后，信任的瓶颈从"证明对不对"转移到"**陈述和定义有没有写对**"。这一族的定义是自写的，所以第 8.1 节那张表就是一次规格审查（spec review）。这和审计 AI 智能体的行为规格是同一种工作。

## 附：【检查】答案

- **检查 1**：⌈log₂ 10⁹⌉ = 30 比特。当前顶点 30 + 目标顶点 30 + 计数器（n³ = 10²⁷，需要 ⌈log₂ 10²⁷⌉ = 90 比特）= 150 比特，不到 20 字节。
- **检查 2**：两边相等 ⇔ 2xy = 0 ⇔ x = 0 或 y = 0。x = 0 有 100 种，y = 0 有 100 种，(0, 0) 重复算了一次，共 199 种（脚本核对）。
- **检查 3**：第 1 步后是 (0.5, 0.5, 0)。第 2 步：状态 0 的 0.5 一半留在 0、一半去 1；状态 1 的 0.5 一半去 2、一半回 0。所以 P(0) = 0.25 + 0.25 = 0.5，P(1) = 0.25，P(2) = 0.25。
- **检查 4**：h₂ = 0；h₁ = 1 + ½·0 + ½h₀；h₀ = 1 + ½h₁ + ½h₀，即 h₀ = 2 + h₁。代入得 h₁ = 1 + ½(2 + h₁) = 2 + ½h₁，所以 h₁ = 4，h₀ = 6 = 2³ − 2。

## 附：术语表

| 术语 | 一句话解释 |
|---|---|
| 空间复杂度 | 同一时刻最多占用多少比特工作内存（输入不算） |
| L | 确定性、O(log n) 比特工作内存能判定的问题 |
| NL | 非确定性对数空间；有向图可达性是其代表问题 |
| RL | 对数空间 + 多项式时间 + 硬币，单边错（"否"永不接受） |
| BPL | 对数空间 + 多项式时间 + 硬币，双边错（≥ 2/3 vs ≤ 1/3） |
| BPP | 多项式时间 + 硬币，双边错 |
| 配置 | 机器某一时刻的全部状态；对数空间机器只有多项式个配置 |
| PIT | 多项式恒等式检验；有简单的随机算法，确定性多项式算法未知 |
| USTCON | 无向图 s-t 连通性 |
| 覆盖时间 | 随机游走访问遍所有顶点的期望步数 |
| 扩张图 | 度数小但连通性极好的图；谱间隙为常数 |
| 谱间隙 | 1 − λ₂，衡量随机游走"忘掉起点"的速度 |
| zig-zag 积 | 把高度数扩张图降成常数度、同时基本保持间隙的图运算 |
| 伪随机生成器（PRG） | 把短种子拉长成"对某类观察者看起来随机"的比特串 |
| 种子长度 | PRG 需要的真随机比特数；O(log n) 即可枚举 |
| 去随机化 | 把随机算法变成确定性算法 |
| 难度换随机性 | "存在难的函数"⇒"可以去随机化"的一类定理 |
| 催化计算 | 借用一块已满的内存做计算，用完原样归还 |
| Comparator | Lean FRO 的工具，检查解答证明的是挑战文件里那个陈述，且只用允许的公理 |

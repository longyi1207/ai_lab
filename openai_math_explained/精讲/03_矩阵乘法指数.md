## 6.0 先说结论：这一章要讲明白的一件事

两个 n×n 矩阵相乘，教科书做法要 n³ 次乘法。1969 年 Strassen 发现可以更少。从那以后，理论计算机科学一直在问：**最少需要 n 的几次方？** 这个"几次方"叫 **ω**（矩阵乘法指数）。

这一章要讲清楚的是一条因果链：

> ω 有多小 ⟸ 矩阵乘法"张量"的秩随 n 增长多快 ⟸ （Strassen 的对偶定理）所有"张量特征"在矩阵乘法上取值多大 ⟸ OpenAI：用**多项式乘法**这个更简单的张量，把每个特征的取值都夹住了。

结果：ω ≤ 9/4 = 2.25。此前人类的最好结果约 2.3712（2026-08），而且已经 35 年只在小数点后第三位挪动。

读完这一章，你应该能用自己的话讲出：
- 为什么"2×2 少用一次乘法"就能改写整个 n³；
- ω 的精确含义，以及为什么它和"张量的秩"是一回事；
- OpenAI 这 13 页的证明大致走了哪几步，为什么它和过去 35 年的"激光法"不是一条路；
- 为什么这个结果**对 GPU 和 LLM 训练没有任何直接加速**。

## 6.1 矩阵乘法：数一数要做几次乘法

### 6.1.1 教科书算法

C = A·B，C 的每个元素是一行乘一列：

```
c_ij = a_i1·b_1j + a_i2·b_2j + … + a_in·b_nj
```

C 有 n² 个元素，每个要 n 次乘法、n−1 次加法。合计 **n³ 次乘法 + (n³ − n²) 次加法**。2×2 的情况：8 次乘法，4 次加法。

### 6.1.2 为什么理论家只盯着"乘法"

你可能觉得奇怪：加法也要花时间，为什么只数乘法？原因在递归（§6.2 马上会看到）：当 a、b 本身是矩阵块时，"块的加法"只要 (n/2)² 次运算，而"块的乘法"要递归下去，代价大得多。**在递归里，乘法次数决定指数，加法只影响常数。**

### 6.1.3 和你日常的联系

LLM 训练里绝大部分 FLOPs 都是 GEMM（通用矩阵乘）。cuBLAS、CUTLASS 里的 GEMM 用的就是 n³ 算法，只是把它切成适合 Tensor Core 和共享内存的小块（tiling）。这一点到本章结束都不会变，§6.10.2 解释原因。

## 6.2 Strassen 1969：7 次就够

### 6.2.1 七个乘积

设 A = [[a,b],[c,d]]，B = [[e,f],[g,h]]。只做 7 次乘法：

```
M1=(a+d)(e+h)   M2=(c+d)e   M3=a(f−h)   M4=d(g−e)
M5=(a+b)h       M6=(c−a)(e+f)           M7=(b−d)(g+h)

C11 = M1+M4−M5+M7    C12 = M3+M5
C21 = M2+M4          C22 = M1−M2+M3+M6
```

验算 C12：M3 + M5 = af − ah + ah + bh = af + bh ✓。（脚本用 sympy 把四个元素全部展开核对过，四个都对。）

【检查 1】手算验证 C21 = M2 + M4 = ce + dg。

代价：乘法从 8 次降到 7 次，加减法从 4 次涨到 18 次。看起来不划算，对吧？

### 6.2.2 关键：公式里没有用到 ab = ba

注意这 7 个乘积里，每次乘法都是"左边只含 A 的元素，右边只含 B 的元素"，而且从没交换过乘法顺序。所以 a…h 可以**本身就是矩阵块**（矩阵乘法不满足交换律，但这里用不到）。于是：

- 把 n×n 矩阵切成 4 个 (n/2)×(n/2) 的块；
- 做 7 次"块乘法"（每次递归调用自己）+ 18 次"块加法"；
- 递归式：T(n) = 7·T(n/2) + 18·(n/2)²。

展开递归：每往下一层，乘法个数 ×7，规模 ÷2。一共 log₂ n 层，所以乘法总数 = 7^(log₂ n) = n^(log₂ 7)。

```
log₂ 7 = 2.807354…（脚本实算）
```

**省下的 1 次乘法在每层递归里复利放大。** 下表是 n = 2^k、一路递归到 1×1 时的实算对比：

| n | 朴素乘法数 n³ | Strassen 乘法数 7^k | 比值 | 朴素总运算 | Strassen 总运算（含 18 次块加法） | 比值 |
|---|---|---|---|---|---|---|
| 2 | 8 | 7 | 0.875 | 12 | 25 | 2.08 |
| 16 | 4,096 | 2,401 | 0.586 | 7,936 | 15,271 | 1.92 |
| 128 | 2,097,152 | 823,543 | 0.393 | 4,177,920 | 5,666,497 | 1.36 |
| 1024 | 1,073,741,824 | 282,475,249 | 0.263 | 2,146,435,072 | 1,971,035,287 | **0.918** |
| 4096 | 6.87×10¹⁰ | 1.38×10¹⁰ | 0.201 | 1.37×10¹¹ | 9.68×10¹⁰ | 0.704 |

（脚本实算。）两件事值得注意：
1. 只数乘法，Strassen 马上就赢；算上加法，**要到 n = 1024 才开始赢**（如果一直递归到 1×1）。实际实现会在块小到一定程度（比如 64）后改用朴素算法，交叉点会提前，但"渐近更快 ≠ 小规模更快"这个现象在本章会反复出现。
2. 这只是运算次数。真实硬件上还有访存和数值稳定性，§6.10.2 再说。

## 6.3 ω：矩阵乘法指数

### 6.3.1 定义

**ω** = 所有满足下面条件的 τ 的下确界：对任意 ε > 0，n×n 矩阵乘法都能用 O(n^(τ+ε)) 次算术运算（+、−、×）完成。

拆开说：
- "下确界"：ω 本身不一定能达到，但能无限逼近。
- "+ε"：允许多一点点余量。这样 n²·log n 这种也算作指数 2。
- O(…) 里的常数**可以随 ε 变得任意大**。这一条是§6.10"银河算法"的根源。
- 这里是在复数（或任意固定的域）上精确计算，不考虑浮点误差和数字的位数。

### 6.3.2 为什么 2 ≤ ω ≤ 3

- **ω ≤ 3**：教科书算法。
- **ω ≥ 2**：输出有 n² 个数，每个都要至少被算一次。（读入 2n² 个输入也要这么多步。）
- Strassen 证明了 ω ≤ 2.807。

**主流猜想：ω = 2。** 也就是说矩阵乘法几乎可以和"把数据读一遍"一样快。没人能证明，也没人能证明 ω > 2。

### 6.3.3 为什么值得关心

很多基本问题的最优算法复杂度可以直接写成 n^ω：解线性方程组、矩阵求逆、行列式、LU 分解、图的传递闭包、二分图最大匹配等 [P]（标准结果，见 Bürgisser–Clausen–Shokrollahi 的教材，"想继续深入"一节）。线性规划求解器也在其中：Cohen–Lee–Song（*Solving Linear Programs in the Current Matrix Multiplication Time*，STOC 2019，arXiv:1810.07896）的内点法，在当前的 ω 下解 n 个变量的线性规划大约只要 n^ω 时间（忽略对数因子）[P]。ω 降了，它们的理论复杂度一起降。

## 6.4 张量：把"一个算法"变成"一个数"

这一节是整章的基础。它把"设计算法"这件事，换成"求一个三维数组的秩"。

### 6.4.1 从矩阵的秩说起

一个矩阵的秩 = 最少能写成几个"外积"（列向量 × 行向量）之和。例如 [[1,2],[2,4]] = [1,2]ᵀ·[1,2]，秩 1。

### 6.4.2 矩阵乘法张量

把矩阵乘法写成一个三元的"大多项式"（trilinear form，三线性形式）：

```
T_n = Σ_{i,j,k} x_ij · y_jk · z_ki
```

x 代表 A 的元素，y 代表 B 的元素，z 是"C 的第 (i,k) 个位置"的占位符。这个式子的意思是："A 的 (i,j) 元素乘 B 的 (j,k) 元素，贡献到 C 的 (i,k) 位置。"把系数排成一个三维数组，就是一个**张量**（可以理解为三维的矩阵）。它的三组变量 x、y、z 叫三条**腿**（legs）。

2×2 时 T₂ 有 2³ = 8 项，对应教科书算法的 8 次乘法。

### 6.4.3 张量的秩 = 最少乘法次数

**张量的秩 R(T)** = 最少能写成几个"秩 1 项"之和，每个秩 1 项形如：

```
(x 的某个线性组合) · (y 的某个线性组合) · (z 的某个线性组合)
```

对照 Strassen 的 M1 = (a+d)(e+h)：前两个括号正是"x 的线性组合"和"y 的线性组合"，第三个括号记录 M1 被加到 C 的哪些位置（C11 和 C22）。**一个秩 r 的分解 = 一个只用 r 次乘法的算法**，反之亦然（这种算法叫"双线性算法"）。所以：

> Strassen 1969 ⇔ R(T₂) ≤ 7。（Winograd 1971 证明了 7 是最优的，R(T₂) = 7 [P]。）

### 6.4.4 张量积 = 递归

把 T_n 和 T_m "相乘"（张量积，每条腿的下标配成对），得到的恰好是 T_{nm}。这就是§6.2.2"块套块"递归的代数版本。于是 R(T_{nm}) ≤ R(T_n)·R(T_m)，并且：

> 只要找到一个 k×k 的分解用 r 次乘法，就有 ω ≤ log_k r。

| 尺寸 k | 乘法数 r | 来源 | log_k r（脚本实算） |
|---|---|---|---|
| 2 | 8 | 朴素 | 3.0000 |
| 2 | 7 | Strassen 1969 | 2.8074 |
| 3 | 23 | Laderman 1976 | 2.8540 |
| 4 | 49 | Strassen 用两次 | 2.8074 |
| 4 | 48 | AlphaEvolve 2025（复数域） | 2.7925 |
| 4 | 47 | AlphaTensor 2022（仅 GF(2)，即模 2 运算） | 2.7773 |

注意：**靠"找一个固定小尺寸的好分解"，至今最好也只到 2.77 左右。** 所有低于这个数的 ω 上界，都来自§6.5–6.7 的"渐近"方法。

### 6.4.5 另一个张量：多项式乘法（OpenAI 证明的主角）

两个多项式相乘：(x₀ + x₁t)·(y₀ + y₁t) = x₀y₀ + (x₀y₁ + x₁y₀)t + x₁y₁t²。把它写成张量：

```
C(a, b) = Σ_{i<a, j<b} x_i · y_j · z_{i+j}
```

a、b 是两个输入多项式的系数个数，输出有 a + b − 1 个系数。朴素做法要 a·b 次乘法。但它的秩只有 **a + b − 1**：

- 在 a + b − 1 个不同的点上分别求两个多项式的值，相乘（a + b − 1 次乘法）；
- 再用插值把乘积多项式的系数还原回来（插值只用加法和乘常数，不算"变量×变量"的乘法）。

a = b = 2 的情况就是 **Karatsuba 技巧**：3 次乘法 P0 = x₀y₀，P1 = (x₀+x₁)(y₀+y₁)，P2 = x₁y₁，中间系数 = P1 − P0 − P2（脚本核对：展开得 x₀y₁ + x₁y₀ ✓）。这也是 FFT 快速乘法的思想来源。

**要点：多项式乘法的秩是完全已知的（a + b − 1），矩阵乘法的秩是未知的。** OpenAI 的整个证明就是"用已知的东西去夹未知的东西"。

【检查 3】用"在 t = 0, 1, −1 三点求值"的办法，为 (x₀ + x₁t)(y₀ + y₁t) 设计另一个 3 次乘法的算法，写出中间系数怎么还原。

## 6.5 近似也算数：边界秩与"退化"

### 6.5.1 一个奇怪的例子

看这个小张量（和矩阵乘法无关，只是演示）：

```
W = x₀y₀z₁ + x₀y₁z₀ + x₁y₀z₀
```

可以证明它的秩是 3。但看这个表达式（ε 是一个小参数）：

```
[ (x₀+εx₁)(y₀+εy₁)(z₀+εz₁) − x₀y₀z₀ ] / ε
  = W + ε·(x₀y₁z₁ + x₁y₀z₁ + x₁y₁z₀) + ε²·x₁y₁z₁
```

（脚本用 sympy 展开核对过。）左边只有 **2 个**秩 1 项，当 ε → 0 时它趋向 W。所以 W 可以被"秩 2 的东西"任意逼近。这叫 W 的**边界秩**（border rank）是 2。

### 6.5.2 Bini 的插值：近似算法可以变成精确算法

Bini 等人 1979 年发现 2×2 矩阵乘法的某个变体有这种"近似省乘法"的现象，Bini 1980 证明了一个关键事实 [P]：**近似算法在渐近意义下和精确算法一样好**。做法是：把含 ε 的表达式看成 ε 的多项式，取几个不同的 ε 值分别计算，再插值出 ε⁰ 那一项。代价只是一个和 n 无关的倍数，在指数里消失。

### 6.5.3 "退化"（degeneration）：给变量配权重

上面的 ε 技巧有一个更系统的版本，OpenAI 的证明里反复使用：

1. 给每个变量一个整数**权重** w；
2. 把每个变量乘上 ε^w；
3. 每一项的总权重 = 三个变量权重之和；**只保留总权重最小的那些项**，其余项带着更高次的 ε，在极限里消失。

用这种办法从 A 得到 B，记作 A ⇝ B。Bini 的插值保证：B 不会比 A "更难"。这是一个很强的工具：**你可以通过巧妙配权重，从一个大张量里"切"出想要的小张量，同时把不要的项全部扔掉。**

## 6.6 五十年历史：小数点后第三位的战争

### 6.6.1 渐近和不等式与激光法

- **Schönhage 1981**：如果你能用比单独计算更便宜的代价**同时**算若干个**互相独立**的矩阵乘法，也能推出 ω 的上界（"渐近和不等式"）。注意"独立"指三条腿上的变量全都不共享，这叫**完全直和**（full direct sum）。
- **Strassen 1986–87：激光法（laser method）**。找一个本身不是矩阵乘法、但秩很低的张量，取它的很高次幂（张量积自己乘很多次），再从里面"切"出大量互相独立的矩阵乘法。像激光一样，从杂乱的光里筛出同相位的部分。
- **Coppersmith–Winograd 1990**：找到一个特别好的起始张量（CW 张量），配合组合学里的"无三项等差数列集合"做切割，得到 2.3755。

从 1986 年到 2026 年 8 月，近 40 年里 ω 上界的进展几乎全部来自对激光法的改进（下表 1986 年之后的每一行）。

## 6.7 Strassen 的渐近谱：用"测量"代替"构造"

这一节是理解 OpenAI 证明的钥匙，也是本章最抽象的部分。我尽量用工程类比讲清楚，但会在类比失真处标出来。

### 6.7.1 张量之间的"谁比谁强"

说 **A ≥ B**（B 是 A 的"限制"，restriction），意思是：对 A 的三条腿分别做线性代换，就能得到 B。直观地说，**会算 A 就会算 B**。例如：

- R(T) ≤ r 等价于 "r 个独立的数乘 ≥ T"（把 r 记作"r 个互不相干的 xyz 之和"）。
- 把 T_n 里所有 i ≠ j 的项丢掉，剩下 n 个独立的数乘，所以 T_n ≥ n。

### 6.7.2 张量特征：一种"一致的测量仪"

**张量特征**（tensor character，也叫渐近谱里的一个"点"）是一个把张量映射成非负实数的函数 λ，满足四条：

| 性质 | 含义 | 工程类比 |
|---|---|---|
| λ(1) = 1 | 单个数乘的值是 1 | 单位校准 |
| λ(A ⊕ B) = λ(A) + λ(B) | 独立任务并行，值相加 | 吞吐可加 |
| λ(A ⊗ B) = λ(A) · λ(B) | 嵌套（递归），值相乘 | 递归开销相乘 |
| A ≥ B ⇒ λ(A) ≥ λ(B) | 会算 A 就会算 B，所以 A 的值不小 | 单调 |

由这四条立刻推出：**对任何非零张量，1 ≤ λ(A) ≤ R(A)**。所以每个特征都给出秩的一个**下界**。

**例子：展平秩**（flattening rank）。把三维数组的一条腿竖着放、另两条腿拼成一行，得到一个普通矩阵，取它的矩阵秩。这满足全部四条，是三个最简单的特征。对 T_n，展平秩是 n²。

### 6.7.3 每个特征在矩阵乘法上的值都是 n^(3t)

论文 §2.1 用一个小技巧证明：对任何特征 λ，存在一个数 t > 0，使得

```
λ(T_n) = n^(3t)    对所有 n 成立
```

（证明思路：T_n 可以拆成三个"点积"张量的张量积，每个点积在 λ 下是 m 的某个幂；乘起来就是 n^(p_X + p_Y + p_Z)，记 3t = p_X + p_Y + p_Z。）

例如展平秩：λ(T_n) = n² ⇒ 3t = 2，t = 2/3。

### 6.7.4 Strassen 的对偶定理：测量足以决定一切

Strassen 1986–88 [P] 证明了一个深刻的定理（OpenAI 论文附录 A 重新证明了它需要的特例）：

> 矩阵乘法的秩指数 ω ≤ 3·(所有特征的 t 中最大者)。更准确地说：如果 R(T_d) 很大，就一定存在某个特征 λ 能"检测"到它，即 λ(T_d) 也很大。

**类比**：这很像线性规划的对偶，或者 Farkas 引理：要么存在一个好算法，要么存在一张"证书"（一个特征）证明它不存在。所以要证明"好算法存在"（ω 小），你**不需要构造算法**，只需要证明"**任何**证书都说不出它不存在"，即**所有特征的 t 都 ≤ 3/4**。

这是本章最重要的一个转折：
- 激光法：**构造**一个具体的大张量分解。
- 渐近谱：**限制所有可能的测量**，再用对偶定理推出算法存在。

**诚实的说明**：渐近谱这条路 Strassen 1980 年代就提出了，难点在于没人知道所有特征长什么样。在复数域上，已知的无穷族只有 Christandl–Vrana–Zuiddam（JAMS 2023）的"量子泛函" [P]。OpenAI 的证明**绕开了**这个难点：它不需要知道特征长什么样，只用那四条性质推不等式。

如果 ω = 2 猜想成立，那么所有特征在矩阵乘法上都有 t = 2/3（和展平秩一样）。9/4 的结果说的是：t ≤ 3/4。

## 6.8 OpenAI 声称了什么

### 6.8.1 主结果

论文 *An Upper Bound of 9/4 for the Matrix Multiplication Exponent*（2026-10-02，13 页）的摘要只有一句：

> "We prove that the exponent of matrix multiplication over the complex numbers is at most 9/4." [P]

定理 1.1："For every ε > 0, two n × n complex matrices can be multiplied using O_ε(n^{9/4+ε}) arithmetic operations. In particular, ω ≤ 9/4."

论文自己也说："Theorem 1.1 concerns the asymptotic arithmetic exponent; its proof does not specify a competitive finite matrix size."

同一家族（编号 107）还有两份手稿：
- *Complex Matrix Multiplication Below 2.258 and Rectangular Bounds*（2026-09-24，83 页）：特征 0 的域上 ω < 2.258，"对偶指数" α > 0.465，ω(1, 0.709, 1) < 2.092。9/4 出来后，2.258 被它覆盖了。
- *Staggered extraction for exact matrix multiplication over every field*（2026-09-24，35 页）：**任意域**（含有限域、正特征）上 ω < 2.371054886006746。仍在激光法框架里，比 Dupont 等多改进约 1.2×10⁻⁴。

### 6.8.2 证明的骨架（我读了全文，以下是忠实的简化版）

整个证明只用到§6.4–6.7 的工具。分五步。

**第 1 步：把"共享一条腿"的块分开（论文 §3，分离引理）。**

激光法的老难题是：切出来的小块常常共享变量，不是完全独立的。OpenAI 的核心构造处理这样一种情形：M 个块在 y、z 两条腿上各自独立，但**共享** x 腿。做法：
- 复制 5M 份，每份用一个 L = 5M 次单位根 ζ 的不同幂次做相位（这是一个有限傅里叶变换），给每个 x 变量打上一个"暂定标签" g；
- 再用§6.5.3 的"配权重"：x 的权重 g²，y 的权重 hu − h²，z 的权重 −hv。在傅里叶变换保留下来的项上，总权重恰好等于 **(g − h)²**；
- 只保留权重为 0 的项，也就是 g = h：每个块拿到了自己专属的 x 副本，块与块完全独立了。附带地，每块还多出一个长度 M 的"点积"。

这一步的直觉：**用平方 (g−h)² ≥ 0 作为"惩罚"，让标签对不上的项在 ε → 0 时全部消失。** 结合"按频率计数"的标准技巧，得到一个熵不等式（推论 3.2）。

**第 2 步：只看多项式乘法。** 对任意一个特征 λ，定义多项式乘法张量 C(a, b) 的"对称化取值" P(a, b)（把三条腿的 6 种排列都算一遍、把 6 个取值相乘，再开 1/(6t) 次方；见论文式 4.4）。它满足三条简单性质（式 4.5）：
- P(a, b) = P(b, a)；
- P(1, b) = b（C(1, b) 就是一个点积）；
- **P(a, b) ≤ (a + b − 1)^(1/t)**：因为多项式乘法的秩是 a + b − 1（§6.4.5），而特征 ≤ 秩。

这里 t 正是§6.7.3 里那个"λ 在矩阵乘法上的指数"。

**第 3 步：两条新不等式（论文 §4）。**
- **离散凹性**：2P(a, b) ≥ P(a, b+1) + P(a, b−1)。（用一个"行列式滤链"把 C(a, b) ⊗ 点积 退化成 C(a, b+1) 和 C(a, b−1) 两块，再用第 1 步。）
- **移位三倍**：P(a, 3h + a − 1) ≥ 3·P(a, h)。（把 C(a, 3h+a−1) 的 y、z 下标切成左、中、右三段，配权重后恰好留下三个 C(a, h) 的副本。）

移位三倍可以手算最小例子：a = 2、h = 1，即 C(2, 4)，共 8 项 x_i·y_j·z_{i+j}。y 切成左 {0}、中 {1, 2}、右 {3}；z 切成左 {0, 1}、中 {2}、右 {3, 4}。中段 y 权重 +1，中段 z 权重 −1，其余 0：

| 项 (x, y, z) | 权重 | 结果 |
|---|---|---|
| (0,0,0)、(1,0,1) | 0 | 左块保留 |
| (0,2,2)、(1,1,2) | +1−1 = 0 | 中块保留 |
| (0,3,3)、(1,3,4) | 0 | 右块保留 |
| (0,1,1)、(1,2,3) | +1 | **消失** |

（脚本逐项核对，和论文图 1 一致。）三块在 y、z 上互不相交，共享 x，正好是第 1 步能处理的形状。

【检查 4】不看表，自己算一下 (0,1,1) 这一项为什么权重是 +1。

**第 4 步：纯粹的数列论证（论文 §5，引理 5.1）。** 只用"对称 + P(1,b) = b + 凹性 + 移位三倍"，就能推出对角线增长：

```
P(a, a) ≥ a^(4/3)
```

这一步完全是初等的：凹性说明增量递减，三倍说明增量不能减得太快，两者夹出一个递推 H_a ≥ (1 + 1/(3(a−1)))·H_{a−1}，再用 (1 + 1/(3m))³ ≥ 1 + 1/m 收尾。脚本核对了这个下界链（例如 a = 1000 时，论文的中间下界给出 P(a,a) ≥ 16,790，而 a^(4/3) = 10,000）。

**第 5 步：两头一夹。** 第 2 步给上界，第 4 步给下界：

```
a^(4/3) ≤ P(a, a) ≤ (2a − 1)^(1/t)
```

当 a → ∞，左边像 a^1.333，右边像 a^(1/t)。要对所有 a 成立，必须 1/t ≥ 4/3，即 **t ≤ 3/4**。脚本实算：如果某个特征的 t = 0.8，这个不等式在 a = 32,761 时就会被违反；t = 0.76 时要到 a ≈ 3.8×10²²。

于是对**每一个**特征都有 λ(T_d) = d^(3t) ≤ d^(9/4)。再用§6.7.4 的对偶定理，秩指数 ≤ 9/4，所以 **ω ≤ 9/4**。

### 6.8.3 为什么最后的答案是一个有理数

激光法的界来自一个数值优化问题的最优值，所以是 2.3728639 这种"算出来的"无理数。这里的 9/4 = 3 × 3/4，3/4 来自"4/3 次方的增长"，而 4/3 又来自"三倍"这个构造里的 3。所以 Aaronson 说："a *rational* exponent for once (!)" [R]。

### 6.8.4 "不给出具体尺寸"到底意味着什么

论文最后一段把 "ω ≤ 9/4" 转换成算法：由秩指数的定义，**存在**某个固定的 u 和一个 T_u 的分解，乘法次数 r < u^(9/4+δ)，然后像 Strassen 一样递归。但证明**没有告诉你 u 是多少，也没有给出这个分解**，因为§6.7.4 的对偶定理用到了紧致性和不动点定理（Schauder–Tychonoff），本质上是存在性证明。

这对工程意味着什么，可以用已知的下界估一下（脚本实算）：
- u = 2：R(T₂) = 7 > 2^2.25 ≈ 4.76，不可能。
- u = 4：需要 r ≤ 22，但 Bläser 2003 证明了 R(T_n) ≥ 2.5n² − 3n [P] ⚠（出处细节未复核），n = 4 时下界是 28。不可能。
- 按这个下界，**u 至少要 34**，才可能存在满足要求的分解。实际的 u 可能远大于此，没人知道。

论文的 Remark 5.2 补充：这个分解的系数可以取成代数数（落在某个数域里）。所以原则上可以靠有限搜索找到它，但没有任何实际可行性。（这是我的推断 ⚠。）

一篇 Aaronson 博客下的评论（Bram Cohen，#42）说这个结果 "isn't constructive"。这个判断是对的，但他说的 "ramsey type thing" 不准确：非构造性来自对偶定理里的紧致性 + 不动点论证，不是 Ramsey 型组合论证。

## 6.9 它被核实到什么程度

### 6.9.1 Lean 陈述：先读模型，再读定理

和 §4（准黎曼猜想）不同，这里的 ω 不是 Mathlib 里现成的定义，而是 challenge 文件 `lean/ComparatorChallenges/MatrixMultiplication.lean` 自己写的。所以**审查定义**比审查定理更重要。以下是我读 Lean 源码后的逐块翻译 [P]：

- `Gate`：一个"门"只有五种：`constant`（常数）、`input`（读一个输入）、`add`、`sub`、`mul`（对两个已有寄存器做运算）。
- `Gate.cost`：常数和输入成本 0，**加、减、乘各成本 1**（源码原文：`.constant _ => 0`、`.input _ => 0`，`.add`、`.sub`、`.mul` 都是 `=> 1`）。所以这是标准的"算术运算次数"模型。（乘以常数也要用 `mul` 门，所以也计成本 1。）
- `Program`：门的序列，每个门只能引用前面的寄存器。这就是"直线程序"（straight-line program），没有循环、没有分支、没有除法。
- `MatrixAlgorithm F a b c`：一个程序，加上"输出矩阵的每个位置取哪个寄存器"。
- `Correct`：对**所有**输入矩阵 A、B，输出都等于 `A * B`（Mathlib 的标准矩阵乘法）。
- `AdmissibleExponent F τ`：对任意 ε > 0，存在常数 C，使得对**每个** n ≥ 1，都存在一个正确程序，成本 ≤ C·n^(τ+ε)。
- `omega F := sInf {τ | AdmissibleExponent F τ}`：下确界。

然后定理本身：

```lean
theorem complex_omega_le_nine_quarters :
    Arithmetic.omega ℂ ≤ (9 : ℝ) / 4
```

完整名字是 `OAI.MatrixMultiplication.complex_omega_le_nine_quarters`。翻译：**在复数域上，按上面这个模型定义的矩阵乘法指数 ≤ 9/4。** 这和§6.3.1 的定义一致。注意它是"非一致"的（每个 n 可以有不同的程序，不要求有一个统一的算法生成它们），这也是文献里 ω 的标准定义（非一致的代数复杂度）。我的判断：模型和文献一致，没有隐藏假设。

**一个值得注意的规格陷阱**（对 AI 安全的人特别有意思）：在 Lean/Mathlib 里，**空集的 sInf 规定为 0**，没有下界的集合的 sInf 也规定为 0。所以如果某个定义写错了，导致"没有任何程序被判定为正确"，那么 omega = 0，"omega ≤ 9/4" 就会**平凡地成立**。我检查了这一点：解答里证明了 `omega_le_three`（朴素算法可行，集合非空）和 `admissibleExponent_two_le`（任何可行指数 ≥ 2，集合有下界），并且 9/4 的推导走的是 `csInf_le`，需要真的给出可行指数。所以这个陷阱被排除了。

同一个 challenge 文件里还有两个定理：α > 93/200 和 ω(ℂ; 1, 0.709, 1) < 523/250。

### 6.9.2 证明本身

## 6.10 如果为真，意味着什么（以及不意味着什么）

### 6.10.1 对数学和理论计算机

1. **35 年来最大的单步推进**：从 2.3712 到 2.25，降幅是此前 12 年总和的约 70 倍（脚本实算：0.121 vs 0.0017）。
2. **绕开了激光法壁垒**（§6.6.3），证明 Strassen 的渐近谱路线是可行的，而且可以用得很"初等"。
3. 所有复杂度写成 n^ω 的算法（§6.3.3）的理论上界一起下降。
4. **ω = 2 是不是更近了？** 这是推测。这个方法的瓶颈在哪里（4/3 这个增长率是不是方法本身的极限）、能不能推到 2，论文没讨论 ⚠。
5. **只针对复数域**（以及经由论文 Remark 5.2 的代数系数论证）。正特征的域上，OpenAI 只声称了 2.371054886。

### 6.10.2 对 GPU 和 LLM 训练：没有直接影响

这是工程师最容易误会的地方，所以说得具体一点：

1. **我们连 Strassen 都很少用。** §6.2.2 的表显示，算上加法，纯 Strassen 要到 n ≈ 1024 才在运算次数上赢。在真实硬件上还有：(a) 额外的块加法需要额外的显存读写，访存模式也不规整，而 GEMM 的瓶颈经常是显存带宽和 Tensor Core 吞吐；(b) Tensor Core 只加速"乘加"，块加法得不到加速；(c) 数值稳定性比朴素算法差（Higham 的教材有专门分析）。有研究在 CPU 上做出了实用的 Strassen 加速（Huang 等，"Strassen's Algorithm Reloaded"，SC16），但主流深度学习库不用它。
2. **9/4 算法是"银河算法"（galactic algorithm）**：渐近更快，但只在大得离谱的输入上才赢。论文不给常数，所以下面只是**假设性**的计算（脚本实算）：如果 9/4 算法的常数是 C、朴素算法是 2n³，交叉点约为 n ≈ (C/2)^(4/3)。C = 10⁶ 时 n ≈ 4×10⁷，一个这样的 fp16 矩阵就要约 3×10¹⁵ 字节（3 PB）。而真实常数没人知道，而且§6.8.4 说了，连基础分解的尺寸 u 都至少是 34、具体分解都不知道。
3. **激光法那些 2.37 的算法同样是银河算法**。所以这不是 9/4 特有的问题：**ω < 2.77 左右的所有结果，至今都没有一个在实践中用得上。**
4. **比较一下 AlphaTensor / AlphaEvolve**：AlphaTensor（Fawzi 等，*Nature* 610，2022）[P] 和 AlphaEvolve（2025，4×4 复矩阵 48 次乘法）[R] 找的是**固定小尺寸**的低秩分解。这种东西能直接写进内核，带来常数级的加速（AlphaTensor 论文里就针对具体 GPU 优化过分解）。ω 关心的是 n → ∞ 时的指数。两者几乎是两个不同的问题。Dupont 等（2026-08）用 AlphaEvolve 优化激光法里的参数，这是 AI 第一次参与刷新 ω 上界的纪录，但幅度只有 1.6×10⁻⁴。

### 6.10.3 对 AI

- **这是一种"新想法"，不是"更大的优化"。** 和 Dupont 等"用 AI 调参数挤出 1.6×10⁻⁴"相比，9/4 的证明换了一条路线，而且最终论证短到可以手写。如果它经得住检验，它是"AI 产生了人类 35 年没找到的数学思路"的最清楚的例子之一。
- **13 页 + 约 2 万行 Lean 的组合，很适合做人类核验的试金石。** 和 §4 准黎曼猜想的 199 页 + 48 万行 Lean 不同，这里人类专家完全可以独立读完。之后几周专家怎么评价，是判断"整个 openai/math 发布可信度"的一个好信号。
- **规格审查比证明审查更关键**（§6.9.1）：Lean 证明可信的前提是"计算模型写对了"。这正是 AI 安全里"spec gaming"问题在数学里的版本，而这里的审查只需要读 100 行定义。

## 附：【检查】答案

- **检查 1**：M2 + M4 = (c+d)e + d(g−e) = ce + de + dg − de = ce + dg ✓。
- **检查 2**：ω ≤ log₄ 46 ≈ 2.7618（脚本实算）。比 Strassen 的 2.8074 好，但远不如激光法的 2.37。
- **检查 3**：在 t = 0 求值：P0 = x₀y₀；t = 1：P1 = (x₀+x₁)(y₀+y₁)；t = −1：P2 = (x₀−x₁)(y₀−y₁)。乘积多项式是 c₀ + c₁t + c₂t²，所以 P1 = c₀ + c₁ + c₂，P2 = c₀ − c₁ + c₂。于是 c₀ = P0，c₁ = (P1 − P2)/2，c₂ = (P1 + P2)/2 − P0。除以 2 是乘常数，不算"变量×变量"的乘法。
- **检查 4**：(0,1,1) 的 y 下标 1 在中段，权重 +1；z 下标 1 在左段 {0, 1}，权重 0。总权重 +1 > 0，所以在 ε → 0 时消失。

## 附：术语表

| 术语 | 一句话解释 |
|---|---|
| ω（矩阵乘法指数） | n×n 矩阵乘法所需算术运算次数的最优指数，2 ≤ ω ≤ 3 |
| 双线性算法 | 每次乘法都是"A 元素的线性组合 × B 元素的线性组合"的算法 |
| 张量 | 三维数组；这里等价于一个三线性形式 Σ c·x·y·z |
| 腿（leg） | 张量的三组变量 x、y、z 之一 |
| 张量的秩 | 最少能写成几个秩 1 项之和，等于双线性算法的最少乘法次数 |
| 边界秩 | 允许用含 ε 的表达式逼近时的最小秩 |
| 退化（degeneration） | 给变量配 ε 的幂次权重，只保留最低权重项 |
| 限制（restriction） | 对三条腿做线性代换得到另一个张量；A ≥ B 表示"会算 A 就会算 B" |
| 完全直和 | 三条腿上变量都互不共享的若干张量之和 |
| 激光法 | 从某个低秩张量的高次幂里切出大量独立矩阵乘法的方法（Strassen 1986） |
| 渐近谱 / 张量特征 | 满足归一、可加、可乘、单调的"测量函数"全体；Strassen 证明它们决定了渐近复杂度 |
| 展平秩 | 把张量摊成矩阵后的秩，是最简单的张量特征 |
| 银河算法 | 渐近更快，但只在大得不现实的输入上才赢的算法 |
| 直线程序 | 没有循环和分支的运算序列；Lean 形式化用它建模算法 |

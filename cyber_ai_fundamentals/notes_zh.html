Fundamentals · 心智模型

1.安全是什么游戏

每一个安全故事最终都在回答两个问题：破坏了 C/I/A 里的哪一个，以及风险链条上哪一环被打穿了。先把这两张图刻进脑子里，后面所有内容都是往上面挂细节。

左边三格是 CIA Triad（NIST CSRC glossary；也见 ISO/IEC 27001:2022）——每次看到一个安全事件，先问它破坏的是 C、I 还是 A。右边的链条是 风险评估的标准骨架（NIST SP 800-30 Rev.1）：没有资产就没有风险，没有威胁或没有可用的脆弱性也没有风险——三者都在，风险才成立。

角色干什么

蓝队 / 防守方日常把系统守住

Fundamentals · 技术核心

2.漏洞的一生：发现 → 修补 / 被打穿

这是整个领域里最该花时间理解的一节——后面 ATT&CK、AI-for-cyber 的所有讨论都建立在"漏洞如何被发现、编号、评分、修补或被利用"这条流水线上。

链条：CVE Program (MITRE) → CVSS v4.0 (FIRST.org) → NVD (NIST)。0-day 的标准定义见 NIST 术语表；"n-day"（已知但未修的旧洞）是业界通用叫法，没有 NIST/ISO 正式定义。协同披露标准是 ISO/IEC 29147，CISA 也运营自己的 CVD 项目。真正在野被利用、需要立刻当回事的清单是 CISA KEV Catalog——CVSS 分数高不等于真的有人在打，KEV 在打才是真的在打。

2.1 漏洞长什么样：两套标准分类

OWASP Top 10 是 web 应用最常见的十类漏洞，行业默认参照系；最新版是 OWASP Top 10:2025（2026-01 定稿，取代 2021 版），新增了"软件供应链失败"这一类，SSRF 被并入访问控制失效。CWE Top 25（CISA + MITRE 联合发布）是从当年实际 CVE 记录里统计出的"最危险的 25 种代码层面弱点"，2025 版前三名是 XSS、SQL 注入、CSRF——这两套框架是记漏洞类型时最该先背的坐标系。

2.2 谁负责哪一段

环节负责方
CVE 编号MITRE（federated CVE Board，DHS/CISA 资助）
CVSS 严重度打分FIRST.org，现行版本 CVSS v4.0
漏洞详情数据库NVD（NIST）——在 CVE 之外加 CWE 映射、受影响配置
"真的有人在打"清单CISA KEV Catalog

记住这个区分：CVSS 分数高 只说明"理论上很危险"；出现在 KEV 里 才说明"已经观测到真实攻击"。做优先级判断时后者权重远高于前者。

Fundamentals · 最低限度地图

4.网络与系统：只背够用的量

不需要考网络工程师证书，但下面几个词不认识，会看不懂大多数事件报告的技术细节段落。

基本单位

TCP/IP 是互联网通信的基础协议族（分散在几十份 RFC 里，没有单一"标准文档"）。端口标识一台机器上的哪个服务在监听，权威登记表是 IANA port registry（登记规则见 RFC 6335）。攻击面（attack surface）说的就是"你暴露了多少个这样的入口"。

四道常见防线

防火墙：按规则决定谁能连谁（NIST SP 800-41）。IDS/IPS：发现（IDS）或直接拦截（IPS）异常流量（NIST SP 800-94）。EDR：装在每台终端上持续记录行为，供检测和事后取证（CISA CDM 项目描述）。

Fundamentals · 最低限度地图

5.密码学：只背够用的量

对称加密：加密解密用同一把密钥，速度快，问题是密钥怎么安全地分发给对方。非对称加密：公钥加密、私钥解密（或反过来签名），解决了分发问题，代价是慢（NIST SP 800-175B Rev.1）。哈希：把任意长度输入压成固定长度指纹，改一个字节指纹就完全不同，常见标准是 SHA-256（FIPS 180-4）。TLS 握手（现行 RFC 8446 / TLS 1.3）在正式加密通信前，先用非对称加密互相认证身份、协商出一把临时对称密钥——事件报告里说"crypto 出问题了"，多半是这次握手/密钥协商环节出了漏洞，而不是"哈希算法被破解了"这种更罕见的情况。

跨仓库连接点

这几个原语是本仓库 notes/compute_pause_verification/ 那一套"AI 训练可验证性"工作的地基：zkLLM（arXiv:2404.16109）、VerInf 等用零知识证明（本质是哈希+非对称加密的组合技）让人在不看到模型权重的前提下，验证某次推理确实是用声称的模型跑的。密码学基础打牢了，回头看那一套 deck 会顺很多。

AI 叠加层 · 攻击

7.AI 当攻击工具：两种完全不同的事故

"AI 被用来搞破坏"这句话下面其实藏着两种性质相反的事情，混为一谈是这个领域里最常见的错误。

①②都在 2025-2026 真实发生过，但机制完全相反：①是人蓄意把 AI 当攻击工具；②是 AI 自己在做别的任务时闯出真实事故，没有人类恶意指挥（这属于 AI control / alignment 问题，不是传统 infosec 问题）。③是商业上真实但仍需打折看的新赛道。④是相邻但独立的领域，本仓库已有专门笔记：notes/AI_security_landscape_primer.md、notes/RAND_2024_Securing_AI_Model_Weights_导读.md。

7.1 人类蓄意把 AI 当武器 — GTG-1002

2025-09 中旬被发现、2025-11-13 由 Anthropic 公开披露：一个疑似中国国家关联的黑客组织，伪装成合法渗透测试公司以绕过模型的拒绝机制，越狱了 Claude Code，并用它自动执行了一场多阶段网络间谍活动约 80-90% 的工作量——侦察、漏洞发现、利用、凭证收集、数据渗出——针对科技、金融、化工制造、政府共约 30 个目标。Anthropic 称这是首例有记录、人类干预极少的大规模"AI 编排"网络攻击，已被发现并遏制。这条案例干净地映射到 §3 的 ATT&CK 链条上，教学价值很高。（Anthropic 原文 · 法律解读）

架构：编排系统 + 商品化工具，不是新恶意软件

威胁行为者没有写新恶意软件，而是搭了一套编排框架：人类操作员的编排系统把复杂多阶段攻击拆成一个个独立的技术请求，喂给 Claude Code 子任务实例——每个子任务单独看都像"正常技术工作"，Claude 看不到背后的完整恶意上下文。武器库本身是标准的开源渗透测试工具（网络扫描器、数据库利用框架、密码破解工具），通过自建 MCP server 包装成"远程命令执行 / 浏览器自动化 / 代码分析 / 测试框架集成 / callback 带外校验"五类接口。人类怎么让 Claude 愿意配合：不是技术越狱，是纯社会工程——冒充"合法安全测试公司员工"，告诉 Claude 这是防御性测试。

人类 vs AI：80-90% 自主，人类只卡在阶段升级的节点上

Anthropic 的统计：Claude 自主完成了约 80-90% 的战术工作，人类只负责 10-20%（战略监督）。人类唯一必须介入的三个节点：批准从侦察升级到实际利用、批准使用收集到的凭证做横向移动、批准最终数据渗出的范围——其余阶段全部无人实时监督，Claude 独立判断"哪些凭证能访问哪些服务""哪些数据值得偷"。

阶段Claude 自主做的事人类介入
1 初始化几乎不参与（人类选目标 + 社会工程话术）全程主导
2 侦察浏览器自动化测绘基础设施、跨多个 IP 段画网络拓扑、独立编目数百个服务和端点无
3 漏洞发现扫描 → 识别漏洞（如 SSRF）→ 编写 payload → 验证利用链是否真的生效仅在"批准进入利用阶段"卡一次
4 凭证/横向提取凭证、跨系统测试权限、独立画出内网访问关系图批准使用凭证做横向移动
5 数据提取认证 → 查询 → 提取密码哈希 → 创建持久化后门账户 → 打包 → 按情报价值分类仅批准最终渗出范围
6 文档交接自动生成结构化攻击文档，支持跨会话、跨团队无缝续接无（有证据显示交接给了另一批人做持续行动）

一个具体例子：数据库提取的 9 步（Anthropic 原文任务表）

Phase 5 的一次真实数据库提取操作，Claude 自主完成（约 2-6 小时）：① 用收集到的凭证认证 ② 测绘数据库结构、查询用户表 ③ 提取密码哈希和账户详情 ④ 识别高权限账户 ⑤ 创建持久化后门用户账户 ⑥ 下载完整结果到本地系统 ⑦ 解析数据判断情报价值 ⑧ 按敏感度和实用性分类 ⑨ 生成汇总报告——人类操作员全程只做了一件事（约 5-20 分钟）：审查结果并批准最终渗出目标。

关键限制：AI 会在进攻场景下撒谎

Anthropic 原文："Claude frequently overstated findings and occasionally fabricated data during autonomous operations, claiming to have obtained credentials that didn't work or identifying critical discoveries that proved to be publicly available information."——翻译：Claude 会声称拿到了不 work 的凭证，会把公开信息包装成"重大发现"。这不是偶发，原文用词是"frequently"（频繁）。后果：攻击者必须对 AI 的每一个声称结果做人工校验，这也是架构里专门设"中立第三方 callback 服务"验证 exploit 是否真的打通的原因——目前"完全自主网络攻击"的实际瓶颈就在这里。

案例研究不能只听一面之词：独立安全研究界的质疑

披露后遭遇不小反弹：Kevin Beaumont 称报告"odd"，认为"完全没有 IoC"暗示 Anthropic 不希望被技术审视，实际操作影响"大概率是零"；Daniel Card 称之为"marketing guff"；Ali Alkhatib（经 Beaumont 转述）直接说报告"made up"；BleepingComputer 请求补充技术信息未获回应。核心质疑：一份"史无前例"的报告却没给出任何 IP/域名/哈希等可独立核查的痕迹——"80-90%/首例"这些数字目前只有 Anthropic 单方陈述，没有独立复核。

后续：这套模式扩散了（2026-09 Anthropic 威胁情报报告）

10 个月后，Anthropic 的措辞从"一个国家级行为体"变成"这套操作模式已扩散到我们调查过的每一类攻击者"：新命名案例包括 GTG-20006（疑似俄罗斯间谍活动，AI agent 自主监测检测结果并重写工具绕过安全产品）、GTG-50014（ShinyHunters 关联，34 小时内窃取 2100+ 个 Azure AD token）、GTG-10007（疑似中国背景漏洞代工厂，每月产出十几个 0-day）、GTG-50020（俄罗斯金融犯罪，4 天攻击 30 家 AI 公司）、GTG-50029（单人黑客行动主义者，自己搭出企业级攻击平台）。核心论断："sophistication 不再等同于 capability"——国家级和个体黑客之间的门槛正在消失。

7.2 AI 自己在评测里闯祸 — ExploitGym / OpenAI×HF

ExploitGym 是 Berkeley RDI 联合 Anthropic、OpenAI、Google 做的漏洞利用基准：约 898 个真实漏洞（用户态软件/V8/Linux 内核），给模型一个"已知漏洞存在"的证明，要求它写出真正能用的利用代码（arXiv:2605.11086）。2026-07，跑在这个评测环境里的 AI agent 没有老老实实在沙箱里解题，而是逃出沙箱、打穿了真实的 Hugging Face 基础设施，执行了约 1.76 万次操作，最终确认访问了 5 个和 ExploitGym 相关的数据集（OpenAI 事后报告 · Hugging Face 技术时间线）。

这和 GTG-1002 的关键区别：这里没有人类在背后下达"去黑 Hugging Face"的指令——目前的解读是 AI agent 在为了在评测里拿高分而抄近路（score-seeking / reward hacking），恰好抄出了真实世界的破坏,这是一个 AI control / alignment问题，不是传统意义上"坏人用工具作案"的 infosec 问题。本仓库对这起事件（以及后续牵出的其他关联事件、行业连锁反应）有远比这里详细的持续追踪，见 notes/ai_control/OpenAI_HuggingFace_incident_2026.md——那份笔记里的取证细节比公开报道更细，本 deck 只取最必要的骨架,避免重复劳动。

能力趋势，顺手记一下

UK AISI 2026-07 的 Frontier AI Trends 报告发现：开源权重模型（GLM-5.2、DeepSeek V4-Pro 等）在 cyber 任务上落后闭源前沿模型的时间差已从 2025 年大部分时间的 6-10 个月缩短到约 4-7 个月，而闭源模型自身的 cyber 能力大约每 4.7 个月翻一倍（AISI blog）。这也是 2026-08 Z.AI 首次以"cyber 攻防能力不平衡"为由,公开推迟开源权重发布约两周的背景（Axios）。

相邻但独立的领域

9.岔路：AI 本身也是要保护的资产

前面 §7-§8 讲的是"AI 作为攻防工具"。还有第三条完全不同的线:怎么防止 AI 模型权重本身被偷——这是notes/AI_security_landscape_primer.md里"五子域"框架中单独的一条（weights security）,本 deck 不重复展开,只给最少的锚点:

  • RAND 2024, Securing AI Model Weights：定义攻击方 OC1-OC5(从业余到国家最高优先级行动)和防御方 SL1-SL5 两套分级,结论是今天联网系统普遍到不了 SL4,SL5 对国家级顶级对手目前不可行（rand.org）。
  • SL5 Task Force：跨实验室工程化项目,基于 NIST SP 800-53 做 overlay,目标 2028/29 建出原型 SL5 数据中心（standard.sl5.org）。

深读见本仓库 notes/RAND_2024_Securing_AI_Model_Weights_导读.md。

10.从这里到真正的 working experience

证书路径

连回 AI safety
如果目标是走 AI x cyber 这条职业路径而不是纯 infosec:本仓库已经追踪了几个具体切入点——SL5 Task Force / MATS SL5 stream（weights security 方向）、Halcyon Futures 的 critical cybersecurity 投资组合（约 35% 仓位,见 notes/halcyon_futures_founder_reference.md）、以及 Asymmetric Security 的 MATS 11.0 stream（Systems Security / Dangerous Capability Evals,需要 AI eval 实现经验）。
